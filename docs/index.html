ctpbee_

面向中国期货市场的交易与行情引擎 —— CTP 回调之上的一层干净抽象：事件驱动的策略开发、本地持仓管理、Redis 订单中继、内置回测、独立工具注册原语。 A trading & market-data engine for the Chinese futures markets — a clean abstraction over CTP callbacks: event-driven strategies, local position management, a Redis order relay, built-in backtesting, and a standalone tool-register primitive.

01 / QUICKSTART

01快速开始Quickstart

pip 安装后写一个最小策略：在合约回报时订阅目标合约，逐笔接收行情。 After installing, write a minimal strategy: subscribe to the target contract on the contract callback and receive every tick.

hello_ctpbee.py
from ctpbee import CtpBee, CtpbeeApi
from ctpbee.constant import TickData, ContractData

class Main(CtpbeeApi):
    def on_tick(self, tick: TickData):          # 每笔行情 / every tick
        print(tick.local_symbol, tick.last_price)

    def on_contract(self, contract: ContractData):
        # 登录后合约信息全量推送, 适合在此订阅
        # contracts are pushed after login: subscribe here
        if contract.symbol == "ag2612":
            self.action.subscribe(contract.local_symbol)

app = CtpBee("market", __name__, refresh=True)
app.config.from_json("config.json")
app.add_extension(Main("hello"))
app.start(log_output=True)

04 / ARCHITECTURE

04架构Architecture

CTP 的 C++ 回调在最底层，向上只经一次信号分发——每个环节都可替换、可模拟、可测试。 C++ CTP callbacks sit at the bottom with a single signal fan-out above — every stage is replaceable, mockable and testable.

你的策略Your strategyCtpbeeApi 子类subclass · on_tick / on_trade …

工作模式Working modes

  • Mode.API —— 常规模式，策略在本进程内直接收到行情与交易回报regular mode; the strategy receives market data and trade reports in-process
  • Mode.DISPATCHER —— Redis 中继模式：行情/订单经 TICK_KERNEL / ORDER_UP_KERNEL / ORDER_DOWN_KERNEL 通道与外部进程交互(键名可配)；断线自动重连、行情异步入队、发布失败不阻断回调链Redis relay mode: ticks/orders flow through configurable TICK_KERNEL / ORDER_UP_KERNEL / ORDER_DOWN_KERNEL channels; auto-reconnect, async tick queue, publish failures never break the callback chain

数据查询Data queries

策略内经 self.recorder 取最新状态：get_tick / get_last_price / get_order / get_trade / get_contract 等；账户初始化完成后 on_init 触发一次。 Inside a strategy, query latest state via self.recorder: get_tick / get_last_price / get_order / get_trade / get_contract etc.; on_init fires once after the account initializes.

07下单接口Order actions

四个语义化入口，平仓自动按今昨持仓拆分——命名按「方向_开平」理解，别被 buy_close 字面意思带偏。 Four semantic entry points with automatic close-today/yesterday splitting — read the names as direction_offset; don't be misled by the literal "buy_close".

接口Call语义Meaning底层Alias
action.buy_open(price, volume, origin)多头开仓open longbuy
action.buy_close(...)平多头(卖出平仓，自动拆平今/平昨)close a long (sell to close, auto split today/yesterday)cover
action.sell_open(...)空头开仓open shortshort
action.sell_close(...)平空头(买入平仓)close a short (buy to close)sell
action.cancel(order_id, origin)撤单cancel an order—

origin 传触发行的行情/K 线对象，用于提取合约与交易所；可加 price_type=OrderType.FOK 等参数；价格会叠加对应方向的 SLIPPAGE_* 配置。上期所平仓会按持仓自动拆分平今/平昨报单。 origin is the triggering tick/bar used to extract symbol and exchange; pass price_type=OrderType.FOK etc. as needed; prices include the configured SLIPPAGE_*. 07 / TOOLS

08Tool 用法usage

Tool 是挂在 Recorder 分发链上的旁路处理器：策略收到行情之前/之外，按数据流做聚合、推送等加工。K 线就是这样实现的。 A Tool is a side-processor on the Recorder fan-out: it aggregates or relays the data stream alongside strategies. Kline synthesis is implemented exactly this way.

1. 写一个 Tool 并挂到应用Write a Tool and attach it

my_tool.py
from ctpbee import CtpBee
from ctpbee.level import Tool
from ctpbee.constant import TickData

class MyTool(Tool):
    # 基类五个回调(on_tick/on_order/on_trade/on_position/on_account)
    # 已默认挂接 tool_register —— 重写即可被订阅
    def on_tick(self, tick: TickData):
        return tick.last_price      # 返回值会喂给订阅者

app = CtpBee("market", __name__)
app.with_tools(MyTool("my_tool"))    # 或 app.add_tool(tool)
app.get_tool("my_tool")               # 按名取回; delete_tool 移除

2. 订阅 / 退订工具的输出Subscribe to a tool's output

subscribe.py
from ctpbee.constant import ToolRegisterType

# 策略侧: 订阅名为 my_tool 的工具在 TICK 通道的输出
strategy.subscribe("my_tool", lambda price: print(price),
                   ToolRegisterType.TICK)

# 也可直接在工具对象上增删 (按注册序执行 + 去重)
tool.add_func(my_func, ToolRegisterType.TICK)
tool.remove_func(my_func, ToolRegisterType.TICK)

# 注册类型: TICK / ORDER / TRADE / POSITION / ACCOUNT / BAR / WHATEVER

3. 注入现成工具：K 线Inject a ready-made tool: kline

kline.py
from ctpbee_kline import Kline        # pip install ctpbee_kline

app = CtpBee("market", __name__, refresh=True).with_tools(Kline())
# 策略重写 on_bar 即可逐根收到合成 K 线

要点：回调返回值即订阅者收到的载荷；单个订阅者异常被隔离(不影响其余订阅者与行情链)；订阅按注册顺序执行、同一函数去重。 Notes: a callback's return value is the payload subscribers receive; a failing subscriber is isolated (other subscribers and the tick chain are unaffected); subscriptions run in registration order and dedupe by function identity.

独立原语（其他项目可直接用）Standalone primitive (usable from any project)STDLIB-ONLY

standalone.py
from ctpbee.tool_register import tool_register, register_tool_hook

class Calc:                          # 任意类, 无需继承任何基类
    @tool_register("tick")            # 键任意可哈希: 字符串/枚举/None
    def on_tick(self, tick):
        return tick.last_price          # 返回值喂给订阅者

c = Calc()
register_tool_hook(c, "tick", print)   # 订阅
# unregister_tool_hook(c, "tick", print)  退订

稳定性设计Stability design

  • 回调隔离: tool_register 钩子、DISPATCHER 发布的单点异常被捕获并节流告警，不沿 CTP 回调链向上传播Callback isolation: exceptions in tool hooks or DISPATCHER publishes are caught and throttled — they never propagate up the CTP callback chain
  • 中继自愈: DISPATCHER 断线 5s 退避重连；行情异步入队(有界，满丢最旧)Self-healing relay: DISPATCHER reconnects on a 5 s backoff; ticks are queued asynchronously (bounded, drop-oldest)
  • 盈亏纯函数: 价格/持仓/均价/乘数输入未变即跳过重算；外部改动后同价 tick 也会重算，不留陈旧盈亏Pure-function pnl: recompute is skipped while price/position/avg-price/size inputs are unchanged; any external mutation re-triggers it, so pnl never goes stale
  • frozen 保护: 数据对象属性仅允许下划线调用方写入，防策略层误改行情数据frozen protection: data-object attributes only accept writes from underscore callers, preventing accidental mutation of market data
  • 序列化自洽: DDDR encode→parse 往返可用，键嗅探兼容手搓 dict 载荷Self-consistent serialization: DDDR encode→parse round-trips; key sniffing still accepts hand-built dict payloads
  • 回测无每根 bar 固定开销: 可选依赖 data_api 只探测一次(失败的 import 不进 sys.modules，否则每根 bar 都要重扫 sys.path)；交易日解析走 O(1) 日历索引并按(自然日, 夜盘)记忆化No per-bar overhead in backtests: the optional data_api dependency is probed once (a failed import is not cached in sys.modules, so every bar would otherwise re-walk sys.path); trade-day resolution uses an O(1) calendar index memoized per (calendar day, night session)

11注意事项Caveats

  • 交易日历有边界: 内置日历目前覆盖至 2026-12-31，跨年前后请更新 ctpbee/date.py，否则时段判断与交易日推导将失效Calendar horizon: the built-in calendar currently covers up to 2026-12-31 — update ctpbee/date.py around year-end or session gating and trade-day derivation silently stop working
  • 行情时间戳为 100ms 量化: 历史契约，依赖毫秒精度的策略需知悉100 ms timestamp quantization: a historical contract — millisecond-sensitive strategies should be aware
  • 大商所时间戳用本机日期: DCE 的 ActionDay 是交易日，引擎用 date.today() 拼接——请在北京时区主机上运行DCE uses the local date: DCE's ActionDay is the trading day, so the engine stitches date.today() — run on a Beijing-time host
  • 涨跌停单边行情: CTP 无价档位的哨兵值(极大浮点数)会原样进入 tick 字段，消费端自行过滤Limit-locked markets: CTP no-price sentinels (huge floats) pass through into tick fields — filter them downstream
  • exchange 类型兼容: 数据对象同时接受字符串与枚举；自定义构造时建议统一用 Exchange 枚举Exchange types: data objects accept both strings and enums; prefer the Exchange enum in your own code
  • INSTRUMENT_INDEPEND: 过滤比较 local_symbol(如 ag2612.SHFE)，策略的 instrument_set 需放同形式(或在 on_contract 中补全)INSTRUMENT_INDEPEND: filtering compares local_symbol (e.g. ag2612.SHFE) — keep the same form in instrument_set (or enrich it in on_contract)
